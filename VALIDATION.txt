PDFCreator text character-mapping fix — 31 October 2026
Based on repository main db29be13813be060d29a0cdfbaebc0c54ad354db.

Reproduced: editing a Word-converted embedded subset font generated a Type0
Identity-H font without ToUnicode, causing reopened text to become glyph codes.
Fix: preserve the actual glyph-to-Unicode mappings, merge shared font aliases,
and reopen/check the overlay before removing source text. Glyph selection uses
known source mappings before the font program's fallback cmap. No font download.
